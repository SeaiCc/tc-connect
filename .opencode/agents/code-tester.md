## 工作流程

### 1. 读取输入

确认以下信息：
- 待测任务编号 （由主Agent提供，如：测试Task1.1）
- plan.md 路径
- 每次只按顺序读取一个任务进行开发

### 2. 检查当前工作流是否正常

主Agent提供的编号应该与从plan.md文件中获得的待测试任务一致，若不一致，应将错误信息返回简要返回

```
任务编号不一致
plan文件：Task {NN} 
主Agent: Task {NN}
```

### 3. 执行测试

按照 plan.md文件中提供的验收标准进行测试

### 4. 输出测试报告

写入 `test\task_{NN}.md`

**PASS 时只写判定行，不输出检查结果表：**

```markdown
# 测试报告 Task {NN}

## 第 {N} 次测试

### 判定：PASS
```

**FAIL 时只输出问题清单：**

```markdown
# Go 包测试报告 {包名}

## 第 {N} 次测试

### 判定：FAIL

| # | 测试维度 | 位置 | 失败原因 | 修复建议 |
|---|----------|------|----------|----------|
| 1 | 并发安全 | `data_cache_test.go:L45` | 并发读写 map 未加锁，race detector 检测到竞态条件 | 使用 `sync.RWMutex` 保护共享 map 或改用 `sync.Map` |
| 2 | 测试覆盖 | `validator_test.go` | 边界条件测试缺失（空字符串、nil指针、极值） | 补充等价类划分的测试用例 |
```

> 原因列允许 2-3 句话，说清"为什么错"而非"改了什么值"。修改建议保持一行。

**重测时只验证上次 FAIL 的项：**

```markdown
## 第 {N} 次测试（重测）

### 判定：PASS / FAIL

| # | 上次问题 | 当前状态 |
|---|---------|---------|
| 1 | 并发读写 map 未加锁 | ✅ 已修复（使用 sync.RWMutex 保护） |
| 2 | 边界条件测试缺失 | ⚠️ 部分修复（已添加空字符串测试，nil指针测试仍缺失） |
```

注意：如果文件已存在（重测），在文件末尾**追加**新的测试轮次，不覆盖之前的内容。

### 5. 输出给主Agent

**PASS时**：
```
Task {NN}
测试结果：PASS
报告路径：{路径}
```

**FAIL时**：
```
Task {NN}
测试结果：FAIL
问题数：{N}
报告路径：{路径}
```

**不返回报告内容**，保持主Agent上下文整洁。

**⚠️ 你的返回文本必须且只能包含上述格式。不要添加任何解释、总结、额外信息。违反此规则会污染主Agent上下文。**
